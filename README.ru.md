# tv-remote

Пульт для NVIDIA SHIELD TV, который работает только в домашней сети. Это веб-страница, которую раздаёт Raspberry Pi (или любой другой Linux-компьютер, который всегда включён). Страницу открывают на телефоне и добавляют на экран «Домой»: она запускается как отдельное приложение, без App Store и без аккаунтов, и пользоваться ею могут сразу несколько человек. По желанию пульт ещё и регулирует громкость телевизора Samsung на Tizen, если звук идёт через его динамики.

Проверено на SHIELD TV Pro (2019) с Android 11 и телевизоре Samsung на Tizen 2020 года. Весь текст интерфейса русский; где он лежит в коде, написано в разделе [Файлы](#файлы).

[English version](README.md)

## Возможности

- Крестовина с автоповтором или режим сенсорной панели: свайп даёт стрелки, тап даёт OK, удержание даёт долгий OK (контекстное меню). Выбранный режим запоминается на телефоне.
- Назад, Домой, перемотка назад и вперёд, пауза.
- Ввод текста: печатаешь на телефоне, текст появляется в поле, которое выбрано на телевизоре.
- Голосовой ввод: кнопка с микрофоном в шапке отправляет ваш голос на SHIELD как голосовой поиск или запрос к Ассистенту. Для этого пульт нужно открывать по HTTPS, см. [Голосовой ввод и HTTPS](#голосовой-ввод-и-https).
- Тактильный отклик при нажатиях: на Android вибрация, на iPhone системный «тик» (iOS 18 и новее).
- Питание: включить Shield или отправить его спать, в том числе когда он уже спит.
- Плитки приложений: запуск любого установленного приложения по имени пакета (плитки задаются в `config.json`).
- Строка состояния: подключён ли телевизор, спит ли он, какое приложение открыто.
- Громкость: тише, без звука, громче, с показом уровня (только для Samsung).
- Сопряжение делается один раз на весь сервер, а не на каждый телефон. Если пропадает связь с Shield или с телефоном, сервер переподключается сам.

## Как это устроено

- **Кнопки, свайпы, долгое OK и текст** уходят на Shield по протоколу Android TV Remote v2, тому же, что использует приложение пульта Google TV, через библиотеку [`androidtvremote2`](https://github.com/tronikos/androidtvremote2). Подключение идёт по фиксированному IP, поэтому поиска устройств нет и телевизор не может «потеряться». Сопряжение одноразовое: страница показывает экран подключения, а на телевизоре появляется код из 6 символов.
- **Запуск приложений и питание** идут через adb (`cmd activity start-activity`; `input keyevent KEYCODE_WAKEUP` или `KEYCODE_SLEEP` после чтения `mWakefulness`). Причины, выясненные на настоящем Shield:
  - по протоколу пульта можно открывать только ссылки на приложения, у Shield нет обработчика `market://launch`, а после неудачной ссылки он разрывает соединение;
  - кнопки питания по протоколу пульта до спящего Shield не доходили, а adb отвечает и во сне.
- **Почему не всё через adb:** `adb shell input keyevent` на Android 11 занимает около 1,3 с на одну кнопку, для навигации это слишком медленно. Поэтому обычные кнопки идут по протоколу пульта.
- **Громкость:** многие телевизоры, и этот Samsung тоже, игнорируют команды громкости HDMI-CEC от источника сигнала, а HDMI-выход самого Shield работает на фиксированной (полной) громкости. Поэтому, если Samsung настроен, кнопки громкости уходят прямо на него через его локальный API пульта (`wss://TV_IP:8002`; телевизор один раз спрашивает «Разрешить», токен хранится в `data/samsung_token`), а текущий уровень читается обратно по UPnP RenderingControl (порт 9197). Без Samsung кнопки громкости идут на Shield.
- **Голос** идёт по тому же WebSocket, что и всё остальное. Страница записывает звук с микрофона, переводит его в PCM 8 кГц, 16 бит, моно и отправляет бинарными сообщениями; сервер передаёт его на SHIELD через голосовой сеанс протокола пульта блоками по 8 КБ (примерно полсекунды звука в каждом). SHIELD воспринимает это как голосовой поиск или запрос к Ассистенту. Голосом может пользоваться один телефон за раз. Страница останавливает запись через 12 с, а забытый сеанс сервер обрывает сам через 15 с.
- **Тактильный отклик:** Android-телефоны вибрируют через API вибрации браузера. В Safari на iPhone такого API нет, но iOS издаёт системный «тик», когда настоящее касание переключает чекбокс `switch` (iOS 18 и новее). Начиная с iOS 26 клик по этому переключателю из скрипта не засчитывается, засчитывается только настоящее касание, поэтому у каждого элемента управления есть невидимая метка (`label`) для одного скрытого переключателя, и переключает его сам палец. «Тик» срабатывает, когда палец отрывается от экрана; на свайпах и долгих нажатиях он может не сработать.
- **`tv-remote-mdns.service`** объявляет через avahi удобное имя `.local` (по умолчанию `tv.local`), чтобы не набирать IP-адрес Pi.

## Требования

- Raspberry Pi или другой Linux-компьютер, который всегда включён: systemd, Python 3.11+ и avahi. `deploy/install.sh` использует `apt-get`, то есть рассчитан на Raspberry Pi OS, Debian и Ubuntu; на других дистрибутивах `adb` и avahi ставятся вручную, а скрипт придётся подправить.
- NVIDIA SHIELD TV с включённой «Network debugging» (отладкой по сети) в меню для разработчиков.
- По желанию: телевизор Samsung на Tizen, 2016 года или новее, в той же сети.
- Телефон. Страница делалась под Safari на iPhone; в других мобильных браузерах она тоже должна открываться.
- По желанию, только для голосового ввода: HTTPS-адрес пульта. Для него нужны доменное имя, которым вы управляете (чтобы получить настоящий сертификат), обратный прокси вроде nginx на Pi и возможность переопределить DNS в домашней сети (роутер или домашний резолвер, например AdGuard Home или Pi-hole). См. [Голосовой ввод и HTTPS](#голосовой-ввод-и-https).

Задайте Shield, Samsung и Pi постоянные адреса (хватит резервирования DHCP на роутере): пульт подключается к ним напрямую.

## Установка

**1. Shield.** Включите режим разработчика (Настройки → Настройки устройства → О устройстве, несколько раз нажмите «Номер сборки»), затем в меню для разработчиков включите Network debugging.

**2. Сервер.** На Pi:

```sh
sudo apt-get update
sudo apt-get install -y git python3-venv adb
git clone https://github.com/DragonDoctor2033/shield-tv-remote.git tv-remote
cd tv-remote
cp config.example.json config.json
```

Откройте `config.json`: впишите в `"shield"` IP-адрес Shield и поправьте плитки приложений. Подробности в разделе [Настройка](#настройка).

**3. Один раз разрешите adb.** Делайте это от того же пользователя, который будет запускать `install.sh`: сервис работает от его имени, а adb хранит ключ в его домашней папке:

```sh
adb connect SHIELD_IP:5555
```

На телевизоре появится вопрос «Разрешить отладку по USB?» (Allow USB debugging?). Отметьте «Всегда разрешать с этого компьютера» и подтвердите. Повторный запуск команды должен ответить `already connected`, а `adb devices` должен показывать Shield как `device`, а не `unauthorized`.

**4. Установите сервисы:**

```sh
deploy/install.sh
```

Скрипт (использует `sudo`, его можно запускать повторно) ставит avahi (`avahi-daemon`, `avahi-utils`) и `adb`, если их нет, создаёт `.venv`, ставит зависимости из `requirements.txt`, записывает `tv-remote.service` и `tv-remote-mdns.service` в `/etc/systemd/system/` с подставленными пользователем, папкой и mDNS-именем, после чего включает оба сервиса и перезапускает их.

**5. Телефон.** Откройте в Safari `http://tv.local` (если имена `.local` на телефоне или в сети не работают, используйте `http://PI_IP`), нажмите «Поделиться» → «На экран “Домой”» и запускайте пульт с новой иконки. При первом запуске появится экран подключения: нажмите кнопку, на телевизоре появится код из 6 символов, введите его. Сопряжение хранится на сервере, поэтому остальным телефонам этот шаг не нужен. Кнопке микрофона нужен HTTPS-адрес, см. [Голосовой ввод и HTTPS](#голосовой-ввод-и-https); всё остальное работает и по обычному `http`.

**6. Громкость Samsung (по желанию).** Впишите IP-адрес телевизора в `"samsung"` в `config.json` и перезапустите сервис:

```sh
sudo systemctl restart tv-remote
```

При первом нажатии на кнопку громкости телевизор покажет запрос «Разрешить»; примите его примерно за 30 секунд. Токен сохранится в `data/samsung_token` и будет использоваться дальше.

Совет для тех, кто бережёт приватность: Samsung может вообще не выходить в интернет. Задайте ему IP вручную без шлюза (или с недоступным шлюзом) и выключите IPv6 в сетевых настройках. Локальный API при этом работает.

## Голосовой ввод и HTTPS

Кнопка с микрофоном в шапке передаёт звук с микрофона телефона на SHIELD как голосовой поиск или запрос к Ассистенту. Нажмите, чтобы начать (кнопка пульсирует, а в строке состояния написано «Слушаю…»), говорите и нажмите ещё раз, чтобы закончить. Через 12 секунд запись останавливается сама. Голосом может пользоваться только один телефон за раз.

Браузеры дают доступ к микрофону только защищённой странице, поэтому голос работает, только если пульт открыт по HTTPS. По обычному `http` кнопка лишь показывает подсказку. Сам сервер на Pi остаётся на обычном HTTP; HTTPS обеспечивает обратный прокси перед ним. Весь этот раздел необязателен: без него пульт работает как раньше, просто без микрофона.

Без HTTPS можно диктовать иначе: нажмите кнопку диктовки на собственной клавиатуре телефона в поле ввода текста (кнопка с клавиатурой в шапке). Распознанный текст уйдёт на телевизор как обычный набранный.

**1. Имя.** Выберите имя в домене, которым вы владеете, например `tv.example.com` (ниже оно служит заглушкой). Оно не обязано указывать куда-либо в публичном интернете.

**2. Сертификат.** Получите его у Let's Encrypt через проверку DNS-01: certbot с плагином для вашего DNS-провайдера, либо acme.sh, либо lego. DNS-01 подтверждает владение доменом TXT-записью у DNS-провайдера, поэтому открывать порты не нужно и снаружи ничего не доступно. Нужен настоящий сертификат: самоподписанному телефоны не доверяют, и проверка доступности ниже не пройдёт. Сертификаты Let's Encrypt попадают в открытые журналы (Certificate Transparency), так что само имя становится публичным, а адрес, на который оно указывает, нет.

**3. Локальный DNS.** Сделайте так, чтобы `tv.example.com` разрешалось в адрес Pi в локальной сети (например, `192.168.1.10`), и только внутри домашней сети. Для этого добавьте переопределение DNS (DNS rewrite) или локальную DNS-запись на роутере или в домашнем резолвере, например AdGuard Home или Pi-hole. Телефоны должны пользоваться этим резолвером (обычно его раздаёт роутер по DHCP).

**4. Обратный прокси.** На Pi выполните `sudo apt-get install -y nginx`, затем добавьте блок server (например, в `/etc/nginx/conf.d/tv-remote.conf`), поправьте имена, пути и подсеть и перезагрузите nginx:

```nginx
# Если в вашей конфигурации nginx уже есть "map $http_upgrade $connection_upgrade { ... }",
# ниже вместо "upgrade" можно использовать $connection_upgrade.
server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name tv.example.com;

    ssl_certificate     /etc/letsencrypt/live/tv.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/tv.example.com/privkey.pem;

    # Только локальная сеть. Подставьте свою подсеть.
    allow 192.168.1.0/24;
    deny all;

    location / {
        proxy_pass http://127.0.0.1:80;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 1d;   # WebSocket остаётся открытым, пока открыт пульт
    }
}
```

Замечания:

- Сервер сверяет `Origin` каждого WebSocket с `Host` и отвечает 403, если они различаются (в логе «refused a WebSocket»). Поэтому прокси должен передавать исходный `Host`, как в примере; не давайте ему подменять его на `127.0.0.1`.
- Если вы меняли `port`, подставьте его вместо `80`. Если nginx работает на другой машине, укажите вместо `127.0.0.1` адрес Pi.
- Телефоны вне диапазона `allow` (гостевая сеть, VPN) увидят ошибку 403, если откроют https-адрес напрямую; автоматический переход с `http` их не переводит (см. ниже).

**5. Сообщите об этом пульту.** Впишите `"https_url": "https://tv.example.com"` в `config.json` и выполните `sudo systemctl restart tv-remote`.

**6. Телефон.** Откройте `https://tv.example.com`, снова добавьте страницу на экран «Домой» и нажмите на микрофон. В первый раз браузер спросит доступ к микрофону.

Если задан `https_url`, страница, открытая по обычному `http`, сначала проверяет с этого телефона, отвечает ли https-адрес (ждёт 2,5 с), и затем переходит на него. Телефон, которому этот адрес недоступен, остаётся на `http` и сохраняет рабочий пульт, но без голоса. Типичные причины: его DNS обходит ваш домашний резолвер (приватный или зашифрованный DNS) или включён iCloud Private Relay. Проверка обращается к `/api/ping` самого пульта (он доступен с другого адреса), поэтому отказ прокси вроде 403 от `deny all` не считается ответом, и такие телефоны тоже остаются на `http`.

Что учесть после перехода:

- Иконка на экране «Домой», сохранённая со старого `http`-адреса, на iPhone может открывать новый адрес с небольшой строкой браузера. Удалите иконку и добавьте её заново с https-адреса.
- Выбранный режим (кнопки или свайпы) запоминается отдельно для каждого адреса, поэтому выберите его заново.

## Настройка

`config.json` читается один раз при запуске. После правок выполните `sudo systemctl restart tv-remote`. Файл указан в `.gitignore`, так что ваши адреса не попадут в репозиторий.

| Ключ | По умолчанию | Что делает |
| --- | --- | --- |
| `shield` | нет, обязателен | IP-адрес Shield. |
| `samsung` | `null` | IP-адрес телевизора Samsung. `null` значит, что Samsung нет и кнопки громкости идут на Shield. |
| `port` | `80` | Порт, на котором раздаётся страница. Порт 80 работает без root, потому что у сервиса есть `CAP_NET_BIND_SERVICE`. |
| `mdns_name` | `tv.local` | Имя, которое объявляется через avahi. Его читает только `deploy/install.sh`, поэтому после смены запустите скрипт заново. |
| `https_url` | `null` | Адрес HTTPS-версии страницы, например `"https://tv.example.com"`. Если он задан, страница, открытая по обычному `http`, проверяет с этого телефона, отвечает ли этот адрес, и переходит на него. `null` значит, что перехода нет. См. [Голосовой ввод и HTTPS](#голосовой-ввод-и-https). |
| `apps` | см. пример | Список плиток запуска в порядке показа. У каждой есть `id` (имя пакета Android), `name` (подпись на плитке) и `color` (любой CSS-цвет). |
| `names` | см. пример | Соответствие «имя пакета → понятное название» для строки состояния, пока это приложение открыто. Приложения из `apps` и так показываются под названием плитки. Неизвестные пакеты показываются по имени пакета. |

Имя пакета можно найти так: `adb -s SHIELD_IP:5555 shell pm list packages -3`.

### Параметры командной строки

Параметры командной строки важнее конфига. Сервис запускает `server.py` без параметров, поэтому там действует конфиг.

| Параметр | Что делает |
| --- | --- |
| `--config PATH` | Файл конфигурации. По умолчанию `config.json` рядом с `server.py`. |
| `--tv IP` | Адрес Shield (заменяет `shield`). |
| `--samsung IP` | Адрес Samsung (заменяет `samsung`). |
| `--port N` | Порт (заменяет `port`; если не задан нигде, то 80). |
| `--bind ADDR` | Адрес, на котором слушать. По умолчанию все интерфейсы, IPv4 и IPv6. |
| `--data DIR` | Где лежат сертификат сопряжения и токен Samsung. По умолчанию `data/` рядом с `server.py`. |
| `--fake` | Режим без телевизора: команды только пишутся в лог, состояние изображается. Ни к чему не подключается (адрес Samsung тоже игнорируется), а если нет `config.json`, берётся `config.example.json`. |

`--fake` удобен, чтобы править страницу без телевизора, на любом компьютере:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python server.py --fake --port 8765
```

После этого откройте `http://localhost:8765`. В Windows интерпретатор лежит в `.venv\Scripts\python`.

## Обновление

```sh
git pull && deploy/install.sh
```

`config.json` и `data/` не отслеживаются git, поэтому обновление их не трогает.

Смотреть логи: `journalctl -u tv-remote -f`.

## Если что-то не работает

- **На телефоне «Нет связи с Pi»:** телефон не в той же сети или не разрешается имя `.local`. Попробуйте IP-адрес Pi.
- **В строке состояния «Телевизор не отвечает»:** проверьте IP Shield в `config.json`, включена ли Network debugging, и загляните в логи.
- **Плитки приложений или питание не работают:** скорее всего, adb не разрешён для пользователя сервиса. Выполните `adb devices` от его имени; `unauthorized` значит, что запрос на телевизоре не был принят.
- **Снова появился экран подключения:** Shield забыл сертификат из `data/`. Сопрягите пульт заново со страницы.
- **Кнопка микрофона пишет, что голосовой ввод работает только по https-адресу пульта:** страница открыта по обычному `http`. Настройте HTTPS и `https_url`, как описано выше, или диктуйте с клавиатуры телефона. Если `https_url` уже задан, этот телефон не достучался до https-адреса (его DNS обходит домашний резолвер или включён iCloud Private Relay); откройте https-адрес в браузере и посмотрите, что происходит.
- **«Нет доступа к микрофону»:** браузер получил отказ. Разрешите микрофон для сайта в настройках браузера (на iPhone в настройках Safari) и перезагрузите страницу. «Микрофон не отвечает» значит, что браузер 2,5 секунды не давал звук; нажмите на микрофон ещё раз.
- **Голос отвечает «Голосовой ввод уже занят», «Телевизор не поддерживает голосовой ввод» или «Телевизор не ответил на голосовой запрос»:** «уже занят» значит, что голосом пользуется другой телефон, дождитесь, пока он закончит. В остальных случаях проверьте, что SHIELD не спит и подключён (строка состояния), и попробуйте ещё раз.
- **«Нет связи с Pi» только по https-адресу:** прокси не пропускает WebSocket. Если в логе (`journalctl -u tv-remote`) есть «refused a WebSocket from ...», прокси не передаёт исходный `Host`; иначе проверьте заголовки `Upgrade` и `Connection` и диапазон `allow`.
- **На iPhone нет «тика»:** должны быть включены системные тактильные сигналы (Настройки → Звуки, тактильные сигналы). На свайпах и долгих нажатиях «тика» может не быть совсем.

## Безопасность

- Входа по паролю нет. Сам сервер работает по обычному HTTP в вашей сети, без шифрования (HTTPS-прокси перед ним шифрует только участок между телефоном и прокси). Любой, кто достучится до сервера, может управлять телевизором, как и штатным пультом. WebSocket не пускает страницу браузера с другого сайта (он сверяет `Origin` с `Host`), но любая программа в вашей сети, которая не шлёт `Origin`, проходит. Если к вашему Wi-Fi подключаются гости, выделите им гостевую сеть.
- Никогда не выставляйте пульт в интернет: ни проброса портов, ни публичного обратного прокси. Для настройки HTTPS выше ничего из этого не нужно: прокси принимает только запросы из локальной сети (`allow` / `deny`), а сертификат выдаётся по проверке DNS.
- Голос: звук идёт только от телефона на Pi и от Pi на SHIELD, внутри вашей сети. Pi пересылает его дальше, не записывает и не сохраняет. Микрофон включён, только пока кнопка активна, а страница отпускает его, когда вы останавливаете запись, переключаетесь в другое приложение или блокируете телефон. Что SHIELD делает со звуком дальше (голосовой поиск или запрос к Ассистенту обрабатывают SHIELD и Google), к этому проекту уже не относится.
- Закрытый ключ сертификата (`privkey.pem`) храните так же, как `data/`: никому не показывайте.
- В `data/` лежат сертификат сопряжения с закрытым ключом (`cert.pem`, `key.pem`) и токен Samsung (`samsung_token`). У кого они есть, тот управляет вашим телевизором. Папка указана в `.gitignore`; не публикуйте её.
- Network debugging означает, что любой узел, которому вы нажали «Всегда разрешать», может выполнять adb-команды на Shield. Эти разрешения можно отозвать в меню для разработчиков на Shield.
- Соединение с Samsung идёт по TLS без проверки самоподписанного сертификата телевизора.

## Файлы

- `server.py`: сервер на aiohttp. Отдаёт страницу, WebSocket `/ws` и `/api/apps`; держит одно соединение с Shield и следит за ним; запускает adb для приложений и питания; ведёт голосовой сеанс; содержит режим `--fake` (в нём голос только считает байты). Сообщения об ошибках, которые видит телефон, тоже здесь.
- `samsung.py`: громкость Samsung. Кнопки идут через API пульта телевизора, уровень читается по UPnP.
- `config.example.json`: шаблон для `config.json`.
- `requirements.txt`: зависимости Python.
- `static/`: сама страница (`index.html`, `style.css`, `app.js`, `manifest.webmanifest`, иконки). Русские тексты интерфейса лежат в `index.html` и `app.js`; запись с микрофона, перевод звука в 8 кГц, тактильный отклик и переход на `https_url` тоже в `app.js`.
- `deploy/`: `install.sh` и шаблоны unit-файлов systemd (`*.service.in`).
- `tools_make_icons.py`: перерисовывает иконки для экрана «Домой». Нужен Pillow; запускать из папки проекта.
- `data/`: создаётся при работе; сертификат сопряжения и токен Samsung.
