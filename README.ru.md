# tv-remote

Пульт для NVIDIA SHIELD TV, который работает только в домашней сети. Это веб-страница, которую раздаёт Raspberry Pi (или любой другой Linux-компьютер, который всегда включён). Страницу открывают на телефоне и добавляют на экран «Домой»: она запускается как отдельное приложение, без App Store и без аккаунтов, и пользоваться ею могут сразу несколько человек. По желанию пульт ещё и регулирует громкость телевизора Samsung на Tizen, если звук идёт через его динамики.

Проверено на SHIELD TV Pro (2019) с Android 11 и телевизоре Samsung на Tizen 2020 года. Весь текст интерфейса русский; где он лежит в коде, написано в разделе [Файлы](#файлы).

## Возможности

- Крестовина с автоповтором или режим сенсорной панели: свайп даёт стрелки, тап даёт OK, удержание даёт долгий OK (контекстное меню). Выбранный режим запоминается на телефоне.
- Назад, Домой, перемотка назад и вперёд, пауза.
- Ввод текста: печатаешь на телефоне, текст появляется в поле, которое выбрано на телевизоре.
- Питание: включить Shield или отправить его спать, в том числе когда он уже спит.
- Плитки приложений: запуск любого установленного приложения по имени пакета (плитки задаются в `config.json`).
- Строка состояния: подключён ли телевизор, спит ли он, какое приложение открыто.
- Громкость: тише, без звука, громче, с показом уровня (только для Samsung).
- Сопряжение делается один раз на весь сервер, а не на каждый телефон. Если пропадает связь с Shield или с телефоном, сервер переподключается сам.

## Как это устроено

- **Кнопки, свайпы, долгое OK и текст** уходят на Shield по протоколу Android TV Remote v2, тому же, что использует приложение пульта Google TV, через библиотеку [`androidtvremote2`](https://github.com/tronikos/androidtvremote2). Подключение идёт по фиксированному IP, поэтому поиска устройств нет и телевизор не может «потеряться». Сопряжение одноразовое: страница показывает экран подключения, а на телевизоре появляется код из 6 символов.
- **Запуск приложений и питание** идут через adb (`cmd activity start-activity`; `input keyevent KEYCODE_WAKEUP` или `KEYCODE_SLEEP` после чтения `mWakefulness`). Причины, выясненные на настоящем Shield:
  - по протоколу пульта можно открывать только ссылки на приложения, у Shield нет обработчика `market://launch`, а после неудачной ссылки он разрывает соединение;
  - кнопки питания по протоколу пульта до спящего Shield не доходили, а adb отвечает и во сне.
- **Почему не всё через adb:** `adb shell input keyevent` на Android 11 занимает около 1,3 с на одну кнопку, для навигации это слишком медленно. Поэтому обычные кнопки идут по протоколу пульта.
- **Громкость:** многие телевизоры, и этот Samsung тоже, игнорируют команды громкости HDMI-CEC от источника сигнала, а HDMI-выход самого Shield работает на фиксированной (полной) громкости. Поэтому, если Samsung настроен, кнопки громкости уходят прямо на него через его локальный API пульта (`wss://TV_IP:8002`; телевизор один раз спрашивает «Разрешить», токен хранится в `data/samsung_token`), а текущий уровень читается обратно по UPnP RenderingControl (порт 9197). Без Samsung кнопки громкости идут на Shield.
- **`tv-remote-mdns.service`** объявляет через avahi удобное имя `.local` (по умолчанию `tv.local`), чтобы не набирать IP-адрес Pi.

## Требования

- Raspberry Pi или другой Linux-компьютер, который всегда включён: systemd, Python 3.11+ и avahi. `deploy/install.sh` использует `apt-get`, то есть рассчитан на Raspberry Pi OS, Debian и Ubuntu; на других дистрибутивах `adb` и avahi ставятся вручную, а скрипт придётся подправить.
- NVIDIA SHIELD TV с включённой «Network debugging» (отладкой по сети) в меню для разработчиков.
- По желанию: телевизор Samsung на Tizen, 2016 года или новее, в той же сети.
- Телефон. Страница делалась под Safari на iPhone; в других мобильных браузерах она тоже должна открываться.

Задайте Shield, Samsung и Pi постоянные адреса (хватит резервирования DHCP на роутере): пульт подключается к ним напрямую.

## Установка

**1. Shield.** Включите режим разработчика (Настройки → Настройки устройства → О устройстве, несколько раз нажмите «Номер сборки»), затем в меню для разработчиков включите Network debugging.

**2. Сервер.** На Pi:

```sh
sudo apt-get update
sudo apt-get install -y git python3-venv adb
git clone https://github.com/DragonDoctor2033/shield-tv-remote.git tv-remote
cd tv-remote
cp config.example.json config.json
```

Откройте `config.json`: впишите в `"shield"` IP-адрес Shield и поправьте плитки приложений. Подробности в разделе [Настройка](#настройка).

**3. Один раз разрешите adb.** Делайте это от того же пользователя, который будет запускать `install.sh`: сервис работает от его имени, а adb хранит ключ в его домашней папке:

```sh
adb connect SHIELD_IP:5555
```

На телевизоре появится вопрос «Разрешить отладку по USB?» (Allow USB debugging?). Отметьте «Всегда разрешать с этого компьютера» и подтвердите. Повторный запуск команды должен ответить `already connected`, а `adb devices` должен показывать Shield как `device`, а не `unauthorized`.

**4. Установите сервисы:**

```sh
deploy/install.sh
```

Скрипт (использует `sudo`, его можно запускать повторно) ставит avahi (`avahi-daemon`, `avahi-utils`) и `adb`, если их нет, создаёт `.venv`, ставит зависимости из `requirements.txt`, записывает `tv-remote.service` и `tv-remote-mdns.service` в `/etc/systemd/system/` с подставленными пользователем, папкой и mDNS-именем, после чего включает оба сервиса и перезапускает их.

**5. Телефон.** Откройте в Safari `http://tv.local` (если имена `.local` на телефоне или в сети не работают, используйте `http://PI_IP`), нажмите «Поделиться» → «На экран “Домой”» и запускайте пульт с новой иконки. При первом запуске появится экран подключения: нажмите кнопку, на телевизоре появится код из 6 символов, введите его. Сопряжение хранится на сервере, поэтому остальным телефонам этот шаг не нужен.

**6. Громкость Samsung (по желанию).** Впишите IP-адрес телевизора в `"samsung"` в `config.json` и перезапустите сервис:

```sh
sudo systemctl restart tv-remote
```

При первом нажатии на кнопку громкости телевизор покажет запрос «Разрешить»; примите его примерно за 30 секунд. Токен сохранится в `data/samsung_token` и будет использоваться дальше.

Совет для тех, кто бережёт приватность: Samsung может вообще не выходить в интернет. Задайте ему IP вручную без шлюза (или с недоступным шлюзом) и выключите IPv6 в сетевых настройках. Локальный API при этом работает.

## Настройка

`config.json` читается один раз при запуске. После правок выполните `sudo systemctl restart tv-remote`. Файл указан в `.gitignore`, так что ваши адреса не попадут в репозиторий.

| Ключ | По умолчанию | Что делает |
| --- | --- | --- |
| `shield` | нет, обязателен | IP-адрес Shield. |
| `samsung` | `null` | IP-адрес телевизора Samsung. `null` значит, что Samsung нет и кнопки громкости идут на Shield. |
| `port` | `80` | Порт, на котором раздаётся страница. Порт 80 работает без root, потому что у сервиса есть `CAP_NET_BIND_SERVICE`. |
| `mdns_name` | `tv.local` | Имя, которое объявляется через avahi. Его читает только `deploy/install.sh`, поэтому после смены запустите скрипт заново. |
| `apps` | см. пример | Список плиток запуска в порядке показа. У каждой есть `id` (имя пакета Android), `name` (подпись на плитке) и `color` (любой CSS-цвет). |
| `names` | см. пример | Соответствие «имя пакета → понятное название» для строки состояния, пока это приложение открыто. Приложения из `apps` и так показываются под названием плитки. Неизвестные пакеты показываются по имени пакета. |

Имя пакета можно найти так: `adb -s SHIELD_IP:5555 shell pm list packages -3`.

### Параметры командной строки

Параметры командной строки важнее конфига. Сервис запускает `server.py` без параметров, поэтому там действует конфиг.

| Параметр | Что делает |
| --- | --- |
| `--config PATH` | Файл конфигурации. По умолчанию `config.json` рядом с `server.py`. |
| `--tv IP` | Адрес Shield (заменяет `shield`). |
| `--samsung IP` | Адрес Samsung (заменяет `samsung`). |
| `--port N` | Порт (заменяет `port`; если не задан нигде, то 80). |
| `--bind ADDR` | Адрес, на котором слушать. По умолчанию все интерфейсы, IPv4 и IPv6. |
| `--data DIR` | Где лежат сертификат сопряжения и токен Samsung. По умолчанию `data/` рядом с `server.py`. |
| `--fake` | Режим без телевизора: команды только пишутся в лог, состояние изображается. Ни к чему не подключается (адрес Samsung тоже игнорируется), а если нет `config.json`, берётся `config.example.json`. |

`--fake` удобен, чтобы править страницу без телевизора, на любом компьютере:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python server.py --fake --port 8765
```

После этого откройте `http://localhost:8765`. В Windows интерпретатор лежит в `.venv\Scripts\python`.

## Обновление

```sh
git pull && deploy/install.sh
```

`config.json` и `data/` не отслеживаются git, поэтому обновление их не трогает.

Смотреть логи: `journalctl -u tv-remote -f`.

## Если что-то не работает

- **На телефоне «Нет связи с Pi»:** телефон не в той же сети или не разрешается имя `.local`. Попробуйте IP-адрес Pi.
- **В строке состояния «Телевизор не отвечает»:** проверьте IP Shield в `config.json`, включена ли Network debugging, и загляните в логи.
- **Плитки приложений или питание не работают:** скорее всего, adb не разрешён для пользователя сервиса. Выполните `adb devices` от его имени; `unauthorized` значит, что запрос на телевизоре не был принят.
- **Снова появился экран подключения:** Shield забыл сертификат из `data/`. Сопрягите пульт заново со страницы.

## Безопасность

- Входа по паролю и шифрования нет: страница и её WebSocket работают по обычному HTTP в вашей сети. Любой, кто достучится до сервера, может управлять телевизором, как и штатным пультом. Достучаться может и веб-страница, открытая в браузере в вашей сети. Если к вашему Wi-Fi подключаются гости, выделите им гостевую сеть.
- Никогда не выставляйте пульт в интернет: ни проброса портов, ни публичного обратного прокси.
- В `data/` лежат сертификат сопряжения с закрытым ключом (`cert.pem`, `key.pem`) и токен Samsung (`samsung_token`). У кого они есть, тот управляет вашим телевизором. Папка указана в `.gitignore`; не публикуйте её.
- Network debugging означает, что любой узел, которому вы нажали «Всегда разрешать», может выполнять adb-команды на Shield. Эти разрешения можно отозвать в меню для разработчиков на Shield.
- Соединение с Samsung идёт по TLS без проверки самоподписанного сертификата телевизора.

## Файлы

- `server.py`: сервер на aiohttp. Отдаёт страницу, WebSocket `/ws` и `/api/apps`; держит одно соединение с Shield и следит за ним; запускает adb для приложений и питания; содержит режим `--fake`. Сообщения об ошибках, которые видит телефон, тоже здесь.
- `samsung.py`: громкость Samsung. Кнопки идут через API пульта телевизора, уровень читается по UPnP.
- `config.example.json`: шаблон для `config.json`.
- `requirements.txt`: зависимости Python.
- `static/`: сама страница (`index.html`, `style.css`, `app.js`, `manifest.webmanifest`, иконки). Русские тексты интерфейса лежат в `index.html` и `app.js`.
- `deploy/`: `install.sh` и шаблоны unit-файлов systemd (`*.service.in`).
- `tools_make_icons.py`: перерисовывает иконки для экрана «Домой». Нужен Pillow; запускать из папки проекта.
- `data/`: создаётся при работе; сертификат сопряжения и токен Samsung.
